# Technology Cost Model

A useful cost model separates expenditure by **economic behaviour**, **service/capability**, and **business ownership**.

## Economic behaviour

| Cost type | Examples | Management implication |
|---|---|---|
| Fixed / committed | contracts, subscriptions, leases | difficult to change inside term |
| Variable / consumption | cloud compute, storage, messaging | optimisation and demand management |
| People | internal teams, contractors | capability and capacity decisions |
| Project / change | implementation, migration, consulting | time-bound investment |
| Risk / control | security tooling, audit, resilience | often indirect return |
| Technical debt | extended support, legacy maintenance | cost of delay and constraint |

## Run / Grow / Transform

A simple executive view can group spend as:

- **Run** — keep current services safe, available and supported.
- **Grow** — extend capabilities to support business growth.
- **Transform** — materially change operating model, platforms or capability.

The categories should not become accounting theatre. Their value is in showing where funding is consumed and whether the portfolio is overly dominated by keeping legacy capability alive.

## Full-cost thinking

Purchase price is rarely total cost.

Consider:

**Licence + Implementation + Integration + Migration + Support + Security + Data + Training + Change + Internal effort + Exit cost**

This is particularly important with SaaS, where a low initial implementation cost can hide long-term per-user and integration costs.

## Cost transparency

Useful reporting should allow an executive to move between:

**Total IT spend → capability/service → vendor/platform → business use → cost driver**

The objective is not chargeback for its own sake. The objective is to make cost understandable enough to manage.
