# Benefits Realisation

Delivery completion is not benefit realisation.

A benefit exists only when the organisation changes and the outcome is observed.

## Benefit lifecycle

**Hypothesis → Baseline → Target → Delivery → Adoption → Measurement → Validation → Sustain / Adjust**

## Benefit categories

- cashable savings;
- cost avoidance;
- capacity released;
- revenue enablement;
- risk reduction;
- service improvement;
- strategic capability.

## Ownership

Where the value occurs outside Technology, the receiving function should validate it.

Examples:
- Finance validates processing-effort reduction.
- Operations validates throughput improvement.
- HR validates onboarding improvement.
- Sales validates CRM adoption and sales-process outcomes.
- Risk validates control improvement.

## Benefit leakage

Expected value can be lost through:
- weak adoption;
- duplicated old processes;
- incomplete retirement of legacy platforms;
- poor data quality;
- unresolved process design;
- unowned operating changes;
- benefits never being measured.

## Review cadence

Suggested checkpoints:
- before investment;
- go-live;
- 30/60/90 days;
- six months;
- annual portfolio review where appropriate.

The frequency should match the nature of the benefit.
